# 系统设计：Pi Agent Workspace

## 1. 状态与方向

这是基于 [原型研究](./super-agent-research.md) 收敛的系统设计。用户已确认该方向并要求开始实现；本文记录首版约束，实现与验证状态见 [README](../README.md)。

**用户已确认：**

- 独立 TUI 应用，复用 Pi，而不是修改 Pi 源码或通过 `/team` 打开扩展界面。
- 人可以创建多个 Agent；Agent 之间可以交谈和协作。
- 左侧可以选择群组或 Agent。
- 群组页面允许人插话；Agent 页面允许进入它的真实上下文并输入 prompt。
- 每群有独立、长期保留的助手；没有 `@` 的消息交给它，明确 `@` 时仅投递选中的成员。
- 助手可自动为公开人类任务创建短名、有职责的 worker，默认不再要求批准，可配置审批；人能 `@` 追加指令，助手仍可继续交谈。
- worker 可归档，公开成果可被当前群成员复用；私密会话不自动共享。创建和运行时读取适用 AGENTS.md。

下述内容是首版实施基线，不表示所有能力已通过实机验证。

核心定义：群助手是长期协作上下文，worker 是可创建、可归档的执行成员。每个成员仍有自己的真实 Pi 会话；宿主确定消息路由、权限和预算，不另设一个 LLM 路由器。这是对早期“仅 @ 唤醒”的明确更新。

## 2. 界面与交互

### 群组视图

```text
┌─ Workspace ──────────┬─ # engineering ───────────────────────┐
│ CHANNELS            │ You: @alice 请实现登录功能             │
│ # engineering   2   │ Alice: @bob 帮我检查接口约束            │
│ # research          │ Bob: @alice 有两个边界条件……           │
│                     │ Alice: 收到，我先调整实现               │
│ AGENTS              │                                         │
│ ● Alice  working    │                                         │
│ ○ Bob    idle       │                                         │
│ ◐ Carol  waiting    ├─────────────────────────────────────────┤
│ + Create agent      │ Message #engineering…                   │
└─────────────────────┴─────────────────────────────────────────┘
```

鼠标点击切换，键盘必须有等价路径。群组只显示协作消息，不默认展示所有工具输出。左侧显示未读、运行和等待人工处理状态。每条人/Agent 消息用独立圆角框包围，真实发送者姓名位于左上角；上图仅示意布局。

### Agent 视图

点击 Alice 后，右侧显示 Alice 的实际 Pi 会话：

- 对话：人直接输入、已投递群消息、其他 Agent 的定向消息、助手回复。
- 工具：正在执行的调用、结果和错误；默认折叠大输出。
- 上下文检查：有效系统提示、可见历史、压缩摘要和工具集合；不承诺读取模型供应商未返回的内部思考。
- 输入动作：下一轮发送、介入当前任务、停止。

这不是给 Alice 另外建立一份无关的私聊会话。切换视图不重建 Agent、不停止运行，也不把消息错误地发给刚切换后的另一个 Agent；发送时绑定收件人 ID。

### 主题、补全与退出

- 通过 Pi 公开主题回调呈现正文与 Markdown；255 色表按持久创建顺序分配 Agent 姓名/边框/侧栏颜色，重启和归档不重新分配。`--colors` 输出完整编号/HEX/色块；超出 255 个历史身份循环，有限色终端近似转换，姓名始终保留。人、Agent、工具和技能采用圆角细线框，终端原生背景，工具底框显示状态/耗时；状态栏不依赖 Powerline 字体；扩展 widgets/status 嵌入工作台，不替换整套布局。
- 复用原生 Editor 的补全菜单、焦点和输入法光标；`/` 搜索命令与 `/skill:name`，`@` 搜索动态 Agent 列表，而不是 Pi 默认的文件补全。菜单高度随内容变化，Tab 优先完成候选。
- 每个 Agent 按自己的 cwd、用户配置与已安装包发现技能；目录进入系统提示，人明确 `/skill:name` 时在投递/steer 边界直接加载正文和相对引用目录。历史和 Agent 消息不触发命令/模板/技能展开。缺失包跳过，不自动安装；技能不得提升工具能力。
- code Agent 接入原生 DefaultResourceLoader、扩展工具/命令/快捷键/生命周期和启用的 MCP/codemode/tool-search；chat/read 不执行扩展工厂。串行加载并清除 Pi 工厂缓存，避免同 cwd 多 Agent 共享插件模块状态。不同插件仍可能自行共享全局文件或进程状态。
- ExtensionUI 按 Agent 隔离 widgets/status；只有当前 Agent 可操作草稿和弹窗，切换/退出取消，后台确认拒绝。保留工作台 header/footer/editor 和命令/快捷键优先级；自定义工具/消息 renderer 仍由工作台通用展示替代。会话替换、tree 导航、reload 拒绝，消息 API 发起的模型回合必须处于工作台队列内。
- 设置向导使用带主题色的圆角框和原生 Input/SelectList；模型、工具档位、群成员、会话切换支持按名称/提供方/描述模糊匹配。成员选择先暂存，Save 后提交，Esc 取消；长说明保留分页与滚轮访问。
- `/quit` 安全退出；Ctrl+C 第一次清空编辑器，500ms 内第二次退出；Ctrl+D 仅空输入时退出。退出路径排空终端响应、停止 TUI、关闭执行器并释放数据库锁；Ctrl+Q 保留为快捷别名。

### 创建 Agent

最小表单：唯一名称、角色说明、模型、工作目录。新 Agent 的模型默认选择继承，不要求重新保存 API key。工具能力在创建时展示并明确选择，凭据不进入聊天记录。

### 模型选择与继承

`/models` 在群页设置群默认，在 Agent 页设置专属模型或恢复继承。群默认跟随启动时读取的 Pi 配置；群消息每次执行按 **Agent 自选 > 消息所属群默认 > Pi 默认** 解析。直接输入没有群归属，继承时采用 Pi 默认。不同群的输入仍串行进入同一个 Agent，会话不拆分。

旧 Agent 原有模型视为明确选择，不自动覆盖。群默认和继承标记复用 SQLite settings 表，专属模型复用 Agent 配置；不修改 Pi 全局设置。群助手始终继承所属群模型（包括直接输入），其 `/models` 操作重定向到群配置。选择从下一回合生效，Pi `setModel()` 在同一个会话上切换，不丢历史、不打断当前回合；不可用模型报错而不是静默改用其他模型。

每个群拥有唯一助手，由 `channel_assistants` 绑定持久 Agent ID；自动加入本群，不允许被成员编辑移除或加入别的群。没有可用模型时不伪造配置，发送报错。普通成员可手工创建，或由群助手在宿主规则内创建。

## 3. 消息、上下文与唤醒

### 唤醒规则

| 输入 | 行为 |
| --- | --- |
| 人在群里发送 `@alice ...` | 保存群消息，向 Alice 投递；仅群内有效成员可被选中。 |
| 人发送不含收件人的群消息 | 保存并投递该群唯一助手。 |
| 人直接向 Alice 输入 | 只进入 Alice 的会话，不自动复制到群里。 |
| Agent 在群里定向请求 Bob | 经通信工具校验后投递 Bob；不是由另一层模型决定路由。 |
| Agent 发布不带收件人的群消息 | 投递群助手；若发送者正是该助手，则只展示，禁止自唤醒。 |
| Agent 直接联系另一 Agent | 在允许的通信范围内入对方收件箱；在人可检查的记录里保留来源。 |
| Agent 回复一个问题 | 不隐式唤醒原作者；需要继续协作时明确指定收件人。 |

`@` 是收件人选择，不是对任意输出做字符串扫描。编辑器把合法名称解析成稳定 Agent ID；通信工具使用结构化收件人。代码块、引用、工具日志里出现 `@alice` 不应自动发消息。不存在或不在群中的目标应提示错误，不静默忽略。

### Agent 通信工具

提供一个小型 `send_message` 工具，负责发送到群组或指定 Agent：正文、目标；因果关联由宿主继承当前投递的链路。发送身份由宿主绑定，Agent 不能自填为 human 或冒充其他成员。

工具先持久化消息和投递记录，再返回接收确认。它不等待对方完成，也不递归调用对方的 `prompt()`；否则 Alice 等 Bob、Bob 等 Alice 会死锁。真正运行由收件队列调度。

普通 worker 的最终文本属于其会话，需要公开成果时用通信工具。**群助手是显式例外**：处理本群输入的最终文本自动发布；若本轮已经公开答复则不重复，收到私下 steer 或被中断则不自动发布。直接输入永不自动转发。超过消息长度的答复保留会话原文，公开截断段带原文位置说明。

### 上下文隔离

每个 Agent 有自己的系统指令、历史、模型和工具集合。群日志不是共享的模型历史。

被唤醒时，投递被提及的消息及所需的有限群上下文，带发送者、群组、消息 ID 和因果关联。近期群消息可作为有界背景投递；不把全群日志重复灌入所有 Agent。投递游标与消息 ID 控制重复上下文。

**直接会话内容不自动广播，不等于强保密隔离。** 同一个 Agent 既参加群聊又看过直接输入，它仍可能在公开回答中透露这些信息。需要严格隔离时应使用不同 Agent/会话和受限通信能力，而不能只依赖“这是私聊”的提示词。

### 人工介入与有限自动交流

- 每个 Agent 的回合串行，来自不同群和直接输入的消息进入同一收件队列。
- 空闲时调用 `prompt()`；忙碌时默认排队。
- 人选择介入时使用 Pi `steer()`，在助手回合和工具调用后的边界生效，不宣称立即中断正在执行的工具。
- 停止调用 `abort()` 并暂停自动收件；停止中的 Agent 不因新消息重新启动，需人工恢复。停止不能撤销已经发生的外部操作。
- 自动互聊继承同一个人类消息的因果链；Agent 不能通过新建消息重置链路计数。
- 每条人类消息默认最多引发 12 次 Agent 执行，全工作台最多并发 128 次执行，人类和 AI 消息共享上限，群助手不额外占槽；每次最多发送 16 条通信消息；达到链路上限显示等待人工继续。计数跨重启保留，调度时原子占用，不按并行分支分别计算。这不是 token/费用/时长硬上限，一次 Pi 执行内仍可能包含多轮工具调用。
- 同目录或父子目录的可写 Agent 按整个回合串行，路径先 realpath；独立目录并发。群助手也不能绕过目录锁；等待不占用预算，结束或取消完成后释放。持锁助手派工后须结束本轮，不轮询等待同目录 worker。
- 工作台有全局暂停与停止。退出应用时停止调度、记录未完成状态并关闭会话；首版不承诺退出后继续执行。

### 有界派工与审批

群助手专有 `create_agent({name,role,task})` / `archive_agent({name})`，普通 worker 不具备这两个工具。宿主验证当前助手身份、所属群、未停止/未被私下 steer、因果根是该群人类请求。默认自动创建；`/autonomy` 可设为审批或关闭，并预授权 worker 的 chat/read/code 上限。模型不能自行选任意目录、升级权限或递归派生。

短名碰撞添加可读后缀，返回实际名称并在群中公告职责；工具只排队，不等待 worker。`@name` 后续输入串行排队，Alt+Enter 使用原有 steer。全工作台最多 128 个未归档 Agent，人工创建、自动 worker 和群助手共用；暂停仍占数量，归档释放名额。取消每任务 3 个／每群 4 个的旧 AI 限制；创建仍受已有 12 回合预算约束，128 并发不等于单任务可自动执行 128 次。超限旧工作台不删已有 Agent，但禁止继续新建且最多同时执行 128 个回合。

`worker_requests` 持久保存 pending/created/rejected；以投递 ID + 工具调用 ID 防重。Agent、成员、创建公告、首条任务投递和提议状态在同一 SQLite 事务提交。待批提议不预占名额；审批重查权限上限、预算和全局未归档总数，满额时保持待批。人工、AI、审批和建群助手统一由 Store.createAgent 校验 128 上限；建群与助手创建在同一事务，失败不留空群。重启不自动批准。`/continue` 也能扩展待批提议的耗尽链路。

### 归档与共享记忆

`/remove` 停止 worker、等待回合结束、释放运行会话、移除群成员并取消剩余投递，不删除 JSONL 或原消息。群助手不可移除。助手的归档工具只允许处理本群自己创建且没有运行/排队工作的 worker。旧名称保留，防止来源混淆。

`memory_search` 在读者当前所属群范围内检索已归档 worker 的公开消息，最多返回 5 个短片段及源消息 ID；`memory_read` 再次校验权限后返回原文。没有自动共享私聊或工具日志。只借鉴 billion-context 的可恢复索引思想，不接入其代理，也不生成额外的层级模型摘要；长期助手继续使用 Pi compaction，原始消息不被摘要覆盖。

## 4. 实现边界

```text
独立应用入口
   │
   ├─ pi-tui：侧栏 / 群消息 / Agent 会话 / 输入与操作
   │
   ├─ 工作台状态：Agent、群成员、消息、投递、暂停与链路计数
   │
   └─ 串行收件队列 + 全局并发限制
          ├─ Alice → Pi AgentSession → Pi SessionManager
          ├─ Bob   → Pi AgentSession → Pi SessionManager
          └─ Carol → Pi AgentSession → Pi SessionManager
```

### 直接复用

- `@earendil-works/pi-coding-agent`：`createAgentSession()`、`SessionManager.create/open`、会话事件、模型/认证、工具、压缩、steer、follow-up 和 abort。
- `@earendil-works/pi-tui`：`HStack`、`VStack`、`ScrollView`、`Editor`、鼠标与可见宽度处理。Pi 也公开导出了多种消息/工具渲染组件，可在适配其依赖后复用。
- Pi 会话存储是模型上下文的唯一权威；不自行重写模型循环或把修改内存消息数组当成持久恢复。

当前实现固定使用 `1.5.0`。已经通过真实 Pi SDK + 本地 HTTP/SSE 模拟模型验证通信工具、会话隔离与恢复、steer 和 abort，以及助手和 worker 在临时目录中真实 write/read/edit/bash 调用；未验证线上模型完整开发工作流。

### 新增的最小状态

使用 SQLite 保存 Agent 配置、群组与成员、唯一群助手、群/定向消息、每个收件人的投递状态、暂停与因果链计数、归档及派工审批。schema 5 兼容旧版；按用户确认一次性把已有未归档 Agent 与 worker 档位升级为 code，保留待批提议、暂停状态、会话映射和明确模型配置，之后不会覆盖人新设的限制。Pi 自己保存会话 JSONL；工作台保存稳定的 Agent ID 到确切 session 文件的映射，恢复时不使用“最近一个会话”猜测归属。

数据目录统一为当前用户的 `~/.pi-workspaces/`，首次启动自动创建；Demo 使用其 `demo/` 子目录并共用根目录的 `owner.lock`。不同项目与安装入口共享同一套真实数据，同一用户仅允许一个工作台进程；第二个实例拒绝启动，不终止旧实例。已有 Agent 保留原 cwd，新 Agent 使用启动项目目录。旧项目 `.pi-workspace/` / `.pi-workspace-demo/` 保留原处，不自动迁移。消息和模型上下文可能包含私密内容；不同 OS 用户的数据不共享。

持久消息用 `(messageId, recipientId)` 防重复排队，但不宣称跨 SQLite、Pi 会话文件和外部工具存在一个全局事务。崩溃发生在开始执行之后而完成记录之前时，标记为 interrupted/需核对，不自动重放有副作用的调用。

### 资源与写入边界

- 每个 Agent 加载用户与已信任项目的已启用资源，遵循 Pi 已保存的信任决定或默认 always；未知项目默认拒绝，需先在原生 Pi 授权。仅 code 加载可执行扩展/MCP，配置使用内存快照，不改写全局配置。通过公开 `loadProjectContextFiles` 在创建时读取/快照适用 AGENTS.md，运行前重新读取并用 `setActiveToolsByName` 重建系统提示，避免 `reload()` 重置共享 provider。不扫描每次工具访问的所有深层子目录；更深规则由 Agent 工作时遵循，不能将提示词当作权限强制。
- 技能目录供模型选择读取，也支持人明确命令展开；仍受既定工具集合限制，不会自行启用未配置 MCP 或提高档位。扩展拥有 OS 用户权限，初始化/命令/MCP 连接不受工作台回合的文件锁沙箱化；只加载可信代码。
- 首版不将应用数据库、其他 Agent 会话或服务凭据作为普通工具可读资源；但任意 shell/宿主权限仍可绕过路径约定，需要真正隔离时采用受限环境。
- 多个可写 Agent 可共享目录，调度器在 claim 前串行化重叠 cwd 树的整个回合。这不是路径沙箱：目录外写入、内部符号链接、其他进程及脱离回合的后台写入不受保护；提示 Agent 不遗留后台写入，真正并行修改应使用独立 worktree。
- Agent 之间的消息不获得人类授权级别，不能凭对方一句话启用更高权限。

## 5. 首版验收

1. 创建 Alice 和 Bob；重启后身份、模型配置和各自会话仍正确关联。
2. 左栏能用键盘和鼠标选择群/Agent；切换不丢输入草稿、不打断后台回合。
3. 群内 `@alice` 只唤醒 Alice；普通群消息唤醒唯一助手；助手的公开回复不自触发，引用不选择收件人。
4. Alice 向 Bob 发消息，Bob 收到来源和必要上下文并可回复；无需人转述，也不阻塞 Alice 的工具调用。
5. 人进入 Alice 的真实会话输入、排队、介入、停止；Bob 不接收该输入。
6. 同一个 Agent 不会同时运行两个 prompt；暂停/停止状态不会被互聊消息绕过。
7. 重复消息、重启、自动互聊达到上限时不会重复启动或无限循环；不确定的旧回合显示需核对。
8. 群消息不会自动包含完整工具日志、其他 Agent 的历史或直接会话输出。
9. 窄终端、中文/emoji、输入法焦点、窗口缩放、滚动和连续流式输出可用。
10. 助手自动创建短名 worker、公告职责，审批开关可用；两个 worker 忙碌时人仍可向助手发消息；归档成果可检索但私聊不可共享，旧 schema 升级/AGENTS 刷新可验证。
11. 用假执行器测试路由、队列、持久化和停止；用本地模拟提供方验证真实 Pi SDK；线上模型联调与实机输入法验收单独记录，不能用模拟测试代替。真实调用需要使用已授权的模型与凭据。

## 6. 实施顺序与非目标

1. **可运行界面**：双栏布局、创建 Agent/群组、持久记录、收件人选择；假执行器验证交互。
2. **接入真实 Pi 会话**：恢复、流式消息/工具、直接输入、排队/介入/停止。
3. **协作闭环**：群消息定向投递、通信工具、自动对话上限、重启核对和集成测试。

首版不做 GitHub/IM 接入、后台 daemon、分布式运行、任务 DAG、向量记忆、完整 Ticket/Mandate 引擎、任意递归派生、自动合并/部署，也不安装或改动用户全局 Pi 配置。

## 8. 首版模块与运行契约

- `src/store.ts`：SQLite 状态、唯一投递、事务、会话路径、启动核对。独占锁不自动猜测失效，异常退出后由人确认进程已停止再解锁。
- `src/workspace.ts`：路由、成员校验、每 Agent 串行/全局并发、因果回合预算、停止与人工继续。Agent 之间只能联系共享群组成员。
- `src/pi-runner.ts`：Pi SDK 适配；受宿主约束的通信工具、原生命令与生命周期、确切会话恢复、真实上下文与事件。
- `src/pi-resources.ts`：原生资源发现、信任和档位过滤、只解析已安装包、隔离工厂实例；少量 Pi 1.5.0 内部辅助 API 的路径固定在此，升级需回归。
- `src/extension-ui.ts`：按 Agent 隔离扩展 UI、编辑器与弹窗权限、取消和清理。
- `src/ui.ts`：pi-tui 全屏工作台，键鼠导航、创建向导、独立草稿与流式对话。
- `src/appearance.ts`：公开 Pi 主题回调、原生 Markdown/Editor、圆角消息/工具/技能框与紧凑状态栏。
- `src/agent-colors.ts`：255 色表、终端色彩转换和完整色表输出。
- `src/dialog.ts`：原生输入/选择组件组成的主题设置弹窗，关键词匹配、键鼠选择与长说明分页。
- `src/completion.ts`：原生命令/技能补全与动态 Agent 候选；禁止把 `@` 当文件路径。
- `src/skills.ts`：只发现已安装技能；验证显式调用并加载带相对引用目录的技能正文。
- `src/cli.ts`：入口、退出清理；`--demo` 使用本地假执行器，不读取模型凭据或调用模型。
- `test/`：Node 内置测试，覆盖路由/恢复/预算/停止及终端组件。

工具档位：`chat`（通信与已授权公开记忆）、`read`（额外 read/grep/find/ls）、`code`（默认，额外 write/edit/bash）。助手和 Agent 直接复用 Pi 原生工具；code 额外复用已启用扩展/MCP，chat/read 保留白名单。创建时或 `/autonomy` 仍可降低 worker 权限。群助手额外拥有受宿主限制的派工与归档工具。read/code 不是沙箱；同一实际目录树可创建多个 code Agent，但回合串行，没有自动 worktree 管理。

运行时依赖固定 Pi 1.5.0、pi-tui 1.5.0 和 TypeBox；SQLite 使用 Node 内置模块，测试使用 Node test runner。要求 Node >=22.19。首版不引入 Web 服务或额外编排框架。
