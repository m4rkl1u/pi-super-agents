# Pi Agent Workspace

基于 **Pi SDK 1.5.0 + pi-tui 1.5.0** 的独立多 Agent 终端工作台。左侧选择群组或 Agent，右侧查看群聊或该 Agent 的真实 Pi 会话；人可以创建 Agent、插话、介入运行，Agent 可以定向互聊。

- [系统设计](docs/system-design.md)
- [DeepSeek 原型与 Pi 能力研究](docs/super-agent-research.md)

这是可运行的本地 MVP，不是无人值守生产系统，也不修改 Pi 源码或全局配置。

## 安装、更新与卸载

要求 Node **22.19+**、npm；启动工作台需要交互终端。安装脚本适用于 **macOS / Linux（Bash）**。Node 22 的 `node:sqlite` 可能打印实验性警告。

### 当前用户安装（默认，无需 sudo）

获取本项目源码，在源码目录运行：

```bash
bash scripts/install.sh                 # 默认安装到 ~/.local
export PATH="$HOME/.local/bin:$PATH"    # 若尚未配置，请加入 ~/.zshrc 或 ~/.bashrc

super-agents                           # 打开共享工作台，新 Agent 默认在当前目录工作
super-agents --demo                    # 离线演示，不调用模型
super-agents --workspace /path/to/project
super-agents --models                  # 列出已配置的可用模型
super-agents --colors                  # 列出 Agent 颜色
super-agents --version
super-agents --help
```

脚本使用锁文件安装构建依赖、编译，然后将打包产物安装为独立副本；**安装后可以移动或删除源码目录**。项目依赖的自动安装脚本被禁用，不会修改 shell 配置、安装 Node 或配置模型凭据。构建会重建源码目录的 `node_modules` 和 `dist`；安装依赖通常需要网络。启动时使用当前目录（或 `--workspace`）作为新 Agent 的默认工作目录；同一用户的所有安装和启动入口共用 `~/.pi-workspaces`，不存在时自动创建，不向项目或程序安装目录写入工作台数据。

### 全局或自定义目录

```bash
bash scripts/install.sh --global                       # 使用 npm prefix --global 的目录
bash scripts/install.sh --prefix "$HOME/tools/agents"  # 自定义目录，支持空格
bash scripts/install.sh --global --prefix /usr/local   # 共享目录，需要写权限
```

自定义目录须将 `<prefix>/bin` 加入 PATH；脚本会输出提示。`--prefix` 优先于 `--user` / `--global`。**nvm 等工具的 npm 全局目录通常仍只属于当前用户**；要供其他 OS 用户使用，应选择所有用户可读、可执行的共享目录，并确保他们的 PATH 中有兼容的 `node` 和该目录的 `bin`。程序全局共享，不共享用户凭据或工作台数据。

脚本不会自动提权。若共享目录需要管理员权限，建议先用普通用户构建打包，再仅对安装操作提权，而不是用 sudo 构建或运行工作台：

```bash
npm ci --ignore-scripts --include=dev
npm pack                              # 自动构建，生成 pi-agent-workspace-0.1.0.tgz
sudo npm install --global --prefix /usr/local --ignore-scripts ./pi-agent-workspace-0.1.0.tgz
```

### 分发给其他用户

也可以发送上述 `npm pack` 生成的 `.tgz`，接收者无需源码或 TypeScript 即可安装（仍需 Node、npm 和运行依赖）：

```bash
npm install --global --prefix "$HOME/.local" --ignore-scripts ./pi-agent-workspace-0.1.0.tgz
export PATH="$HOME/.local/bin:$PATH"
super-agents --demo
```

包名仍为 `pi-agent-workspace`，可执行命令为 **`super-agents`**。包中只包含运行代码、文档和安装/卸载脚本，不包含项目状态、凭据、测试或本机 `node_modules`；未发布到 npm registry。升级版本后请使用实际生成的 `.tgz` 文件名。

### 更新与卸载

更新：先退出工作台，取得新版源码后，重新运行安装命令，使用**同一个安装目录**；或安装新版 `.tgz`。不会自动下载更新。

```bash
bash scripts/install.sh                              # 更新当前用户版本
bash scripts/install.sh --global                     # 更新 npm 全局版本

bash scripts/uninstall.sh                            # 卸载 ~/.local 中的版本
bash scripts/uninstall.sh --global                   # 卸载 npm 全局版本
bash scripts/uninstall.sh --prefix /custom/prefix    # 卸载指定目录中的版本
```

源码已删除或通过 `.tgz` 安装时，直接使用 npm 卸载：

```bash
npm uninstall --global --prefix "$HOME/.local" --ignore-scripts pi-agent-workspace
# 全局安装省略 --prefix；自定义安装使用对应的 --prefix。
```

卸载只移除应用及其命令，**保留 `~/.pi-workspaces/`、旧项目的 `.pi-workspace/` / `.pi-workspace-demo/` 和 Pi 模型凭据/设置**，不修改 PATH 或删除共享安装目录。多处安装时分别卸载；可用 `command -v super-agents` 确认当前命中哪个版本。

## 从源码启动（开发）

```bash
npm ci --ignore-scripts
npm run build
npm run demo
```

原有 `npm start -- ...` / `npm run demo` 用法保持不变。

### 先试离线演示

Demo 自动创建 Alice、Bob、`#general` 和它的专属助手，**不读取模型凭据、不访问模型、不执行文件工具**。在群里输入：

```text
@alice 协作检查这个设计
```

Alice 会定向请 Bob 检查，Bob 发布结果后由群助手回应，不会再次唤醒 Alice。直接输入 `你好` 会由群助手回答；输入 `派工检查这个设计` 会演示自动创建一个有名字和职责的 worker，然后可以用 `@scout`（重名时如 `@scout-2`）追加指令。点击 Agent 可以查看其会话并直接输入。Demo 是确定性的本地模拟，不代表模型的实际推理能力。

### 使用真实 Pi 会话

复用本机 Pi 已配置的模型/凭据（遵循 Pi 的 `PI_CODING_AGENT_DIR` 设置），无需在工作台输入或保存 API key：

```bash
npm start -- --colors         # 列出全部 255 种 Agent 颜色（编号、HEX、色块），无需凭据
npm start -- --models         # 列出可用模型，不发送聊天请求
npm start                    # 打开真实工作台
npm start -- --workspace /absolute/path/to/project
```

有可用模型时，每个群自动拥有一个专属助手（如 `general-assistant`），保留独立的 Pi 会话；启动本身不发送聊天请求。可直接向群助手描述任务，也可以按 **F2** 手动创建成员。模型和工具档位可输入关键词筛选，不需要手写完整标识。模型列表与 Pi 默认配置在启动时读取；修改 Pi 模型配置后需要重启本应用。

### 群默认模型与 Agent 自选模型

- 在 `#general` 等群页输入 **`/models`**，输入模型名或提供方关键词，↑↓ 选择、Enter/Tab 确认。群默认选择 **Follow default / 跟随默认**，使用 Pi 默认模型，也可以单独指定模型。
- 在 Agent 页输入 **`/models`**，可以指定该 Agent 的模型，或选择 **Follow default / 跟随默认** 恢复继承。
- 群消息的优先级：**Agent 自选模型 > 消息所在群的默认模型 > Pi 默认模型**。直接输入没有所属群，继承时使用 Pi 默认模型。
- **新建 Agent 默认继承**；旧 Agent 已有的明确模型配置不被覆盖。修改模型从下一回合生效，保留同一个 Pi 会话与历史，不中断正在执行的回合。
- 群助手固定使用自己所属群的默认模型，包括进入它的直接会话时；在助手页 `/models` 也修改该群配置。
- 选择只保存在工作台，不修改 Pi 全局配置。

### Thinking effort（思考强度）

- **Shift+Tab** 快速循环当前模型支持的档位；**`/thinking`** 打开选择器，也可直接输入 `/thinking high` 或 `/thinking inherit`。
- 与 Pi 一样按模型能力筛选 `off / minimal / low / medium / high / xhigh / max`；不支持思考的模型固定为 `off`。切换模型时按 Pi 的规则适配有效档位，不覆盖保存的偏好。
- 群页修改群默认；Agent 页设置独立覆盖或恢复继承；群助手页修改所属群设置。群任务按 **Agent 覆盖 > 群默认 > Pi 默认** 解析，普通 Agent 私聊不继承群设置。Pi 默认优先使用模型专属 thinking 配置，然后全局默认，未配置时为 `medium`。
- 底部 `thinking:` 显示当前页面下一回合的有效档位；Agent 页按私聊配置显示，从群收到的任务仍按该群配置解析。设置保存在工作台，重启保留，不修改 Pi 全局配置；**下次任务生效，不打断运行中的任务**，也不清空会话。弹窗中不响应 Shift+Tab 快切。
- Demo 可以体验基本档位切换，但不会调用模型。

模型按实际请求计费。**没有 `@` 的群消息会调用该群助手**；明确 `@` 则仅投递指定成员。单纯切换页面和查看上下文不调用模型；启动时会继续处理已授权且未暂停的排队消息。不启用空闲模型预热。

## 外观与技能

界面读取 Pi 当前主题设置（内置主题或用户主题），复用 Pi 原生 Editor/SelectList 和 Markdown。人类、Agent、工具及技能使用截图式圆角细边框：标题在上边框，工具状态与耗时在下边框，正文保留终端原生背景。底部显示运行/排队数、thinking 档位、模型、工具档位与工作目录，不依赖特殊字体；扩展的 widget/status 嵌入工作台，不替换整体布局。

内置 **255 种不重复的 RGB 配色**，通过 `npm start -- --colors` 查看全部编号、HEX 和色块。按 Agent 持久创建顺序分配，群聊、会话、流式消息与侧栏保持一致；重启、增加或归档成员不会改动既有配色。颜色只用于姓名/边框，Markdown 保留主题高亮；始终显示姓名，不单靠颜色辨认。超过 255 个历史身份会循环复用；非 True Color 终端会近似转换，部分颜色可能相同。

- 输入 **`/`** 弹出命令和技能菜单；支持 Pi 的模糊搜索，例如 `/pony` 可以找到 `/skill:ponytail`（若已安装）。↑↓ 选择、Tab 补全、Esc 关闭；菜单打开时 Tab 不会跳到侧栏。
- 输入 **`@`** 弹出现有 Agent；新建 Agent 会即时出现，非当前群成员有提示，最终发送仍经过成员校验。
- 设置向导采用主题色细线圆角弹窗；`/models`、工具档位、`/switch` 和 `/members` 支持关键词模糊匹配。成员列表可逐项勾选，最后 Save；Esc 放弃尚未保存的选择。
- 人类显示为 **`you`**，当前群的主助手显示为 **`ai`**，worker 保留自己的名字。这只是显示别名，不修改身份、会话或 `@` 路由。人类使用中性边框，AI 使用对应身份颜色的边框。普通阅读隐藏投递 JSON，F4 上下文检查仍显示原始内容。
- 群页与 Agent 页都实时显示 AI 增量文本；工具按调用 ID 更新同一块，支持 `pending/running/done/error/interrupted` 状态和工具实际提供的部分输出。无增量事件的工具在结束时显示结果，不模拟进度；长输出默认折叠，运行时保留最新几行。
- 技能按自身名称显示；读取已安装的 `SKILL.md` 也会标明技能名。技能不是独立执行引擎，其实际产出通过本次 AI/工具流展示。F5 或 Ctrl+O 展开技能正文及工具参数/结果。
- 群页只投影主助手处理该群请求的片段，不复制完整会话；私聊和私下 steer 之后的输出不进入群页。自动发布的同一条最终回复不会重复显示；会话压缩后无法恢复的中间过程退回已保存的公开回复。
- 在 **Agent 页**使用 `/skill:名称 任务`；在**群页**不带 `@` 时由群助手处理，带 `@alice` 时只发给 Alice，不唤醒全员。
- 每个 Agent 按**自己的 cwd** 发现 Pi 用户目录、已信任项目和已安装包中的技能，遵循路径与启用设置；原生技能目录会放入系统提示，允许模型按技能说明选择读取。安装/修改资源后重启刷新。
- 本次**人类明确调用** `/skill:` 时直接注入正文和相对引用目录；历史或 Agent 互发的斜杠文本不会自动展开或执行命令，也不会把展开后的正文写入群聊。
- 不自动安装包或提升工具档位。Demo 只模拟技能选择与路由，不执行扩展或真实工具。

### Pi packages、扩展与 `/todos`

真实模式的 **`code` Agent** 会复用已安装、已启用的 Pi 扩展：工具、命令、快捷键、生命周期，以及启用的内置 MCP / codemode / tool-search。`chat/read` 不执行扩展工厂，保留原有工具白名单。每个 Agent 有独立的扩展实例和会话状态；在群页操作扩展时，目标是该群助手。

- **`todo` 是工具名，交互命令是 `/todos`**（由 `@juicesharp/rpiv-todo` 提供）。安装并启用该包后，在 code Agent 页输入 `/todos`；`/` 菜单同时显示该 Agent 的扩展命令、prompt templates 和 skills。
- prompt template 的 `/名称 参数` 经正常队列交给 Agent；扩展命令在当前 Agent 执行。工作台同名命令和快捷键优先，例如 `/models`、`/thinking`、Shift+Tab、Ctrl+S。
- 支持通知、状态文字、编辑器上下方 widgets、选择/确认/输入、多行编辑器和自定义弹窗。后台 Agent 不能读取/覆盖当前草稿或抢占弹窗；切换页面、超时或退出会取消对话框，确认默认拒绝。
- 保留工作台自己的 header/footer/editor；不支持扩展整体替换它们、自定义补全提供方或运行中改主题。工具结果仍用工作台渲染器展示，不承诺原生插件的自定义工具/消息 renderer。替换会话、切换 session tree、`reload` 被明确拒绝；扩展不能在队列之外通过 Pi 消息 API 启动模型回合。
- 遵循 Pi 已保存的项目信任决定（或 `defaultProjectTrust: "always"`）；未知项目默认不信任，不会在工作台中弹出信任授权。需要项目资源时先在原生 Pi 中确认项目可信，再重启。缺失包请用 Pi 安装，本应用不会下载依赖或改写 Pi 资源配置。

**扩展是以当前 OS 用户权限执行的代码，不是沙箱。** 打开 code Agent 会加载其扩展；MCP/插件可能连接服务、启动子进程或执行其他副作用，即使还没向模型发消息。只启用可信插件；第三方插件若使用全局文件或进程状态，不能保证其自行维护的数据按 Agent 隔离。

## 协作规则

- 不带有效提及的人类群消息由专属助手处理；通过 `@alice` 则只选中 Alice。不存在或不属于该群的名称会报错并保留输入。引用、代码块、行内代码里的 `@` 不选择收件人。
- Agent 的 `send_message({ channel, to, text })` 使用结构化收件人，宿主绑定发送身份；不扫描普通助手输出。省略 `to` 的群消息由群助手接收，但助手自己的回复不唤醒自己。
- Agent 只能向自己所在群发消息，或直接联系共享群的成员。成员资格在发送和出队时分别检查。
- 一个 Agent 对应一个独立、持久 Pi 会话。切换到 Agent 页面就是查看这份会话，不是另起一份 DM 历史。
- 群助手处理群输入后的最终文本自动发布；已经通过工具发布过答复则不重复。普通 worker 用通信工具公开成果。直接输入不自动公开，私下 steer 后也不自动转发该回合最终答复。
- 每 Agent 的回合和工具调用串行，全工作台最多 128 个并发回合，人类与 AI 消息共享同一上限，群助手没有额外槽。不同 Agent 的模型流真正并行，包括同目录/父子目录的 `code` Agent；worker 忙碌不会仅因目录相同而阻塞群助手回复。文件保护在工具调用时检查，冲突立即返回，不把整个会话排队。`@worker` 的追加指令进入其队列；需要当前回合介入时进入该 Agent 页 Alt+Enter。
- 每个人类消息的整条自动协作链默认最多 12 次 Agent 执行，每次最多发送 16 条通信消息。Agent 不能自行重置预算。
- **这不是 token、费用或时长硬上限**：一次 Pi 执行内可能有多轮工具调用，生产化仍需额外的消费与运行时限制。

## 自动派工、长期群上下文与记忆

- **默认自动派工，不重复要求批准。** 群助手可用 `create_agent` 为具体的公开人类任务选择短名（如 `scout`、`builder`、`tester`），说明职责并排队执行。重名时添加短后缀，群里显示实际名字；你可直接 `@名字` 追加指令，助手不等待所有 worker 完成才继续与你交谈。
- `/autonomy` 可切换为人工审批或禁用。审批模式先保存并展示提议，`/approve` 决定；重启不会自动批准。权限下降、预算耗尽等条件会在批准时再次校验。
- 默认自动 worker 是 `code`，继承 Pi 原生文件和命令工具；可在 `/autonomy` 降为 `read` / `chat`。助手不能替人升级限制、选择任意目录或递归派生。自动 worker 继承群模型和群助手目录，同目录可并行思考、交流和修改不同文件；涉及同文件或目录树写入时协调所有权。派工后助手不应轮询等待 worker，尤其不能持有写锁等待同伴。
- 全工作台最多 128 个未归档 Agent，人工创建、AI 创建和群助手合计计数；暂停仍占数量，归档后释放名额。取消每任务 3 个／每群 4 个的独立 AI 限制。待批提议不预占名额，批准时重新检查总数。旧工作台超过上限时保留已有 Agent，但不能继续新建，运行并发仍受 128 限制。私聊或私下 steer 不能被用来自动公开派工。
- 128 是全局数量和并发上限，不会扩大单条人类任务默认 12 次执行的协作预算；预算耗尽需人类 `/continue`。
- 每群助手身份和 Pi 会话长期保留，不允许 `/remove`；长上下文由 Pi 自带 compaction 管理，**并非无限 token 窗口或后台常驻**。普通 worker 可由人移除，助手也可归档自己派出的空闲、无排队任务 worker。
- 移除采用归档：停止运行、取消未执行投递、移出成员与 `@` 列表，但保留消息、AGENTS 创建快照和原始 Pi JSONL；名字不再复用，避免把旧来源认作新人。
- `memory_search` 返回归档 worker 的公开成果片段和来源 ID，`memory_read` 按需取原文；群助手和当前群成员都能使用，成员撤销即时生效。**不共享私聊、完整会话或工具日志。** 人也可 `/memory 关键词` 查阅。
- 这里只借鉴 billion-context 的“短索引 → 原始来源按需恢复”思路，没有装入其代理或双重压缩。当前是有界关键词检索，不是向量库或模型生成的分层摘要；原始内容没有被摘要覆盖。

## 工具与安全边界

新助手、手动 Agent 和默认自动 worker 使用 `code`，直接由 Pi SDK 创建原生工具，不另写文件/shell 执行器；创建时仍可选择更低权限：

| 档位 | 工具 |
| --- | --- |
| `chat` | `send_message` + `memory_search` / `memory_read` |
| `read` | 通信/公开记忆 + read / grep / find / ls |
| `code`（默认） | 上述工具 + write / edit / bash + 已启用的 Pi 扩展工具 |

群助手额外拥有宿主约束的 `create_agent` / `archive_agent`；普通 worker 没有派生能力。

按本次确认的升级范围，首次打开旧工作台时，schema 5 会把已有未归档助手/Agent 及自动 worker 档位升级为 `code`；保留会话、历史、模型、暂停状态和待批提议。升级后新设的 `chat/read` 限制不会在后续启动时被覆盖。

共享目录采用进程内的协作式文件保护：

- 原生 `read` 使用短暂共享文件锁；`write/edit` 按真实文件路径独占，不同文件可并行。符号链接及新文件已有父目录会解析为真实路径。
- 覆盖已有文件前必须用原生 `read` 读取；宿主比较 SHA-256，内容已变化或被删除就拒绝操作。重新读取、协调后才能修改；会话重建后需重新读取。新文件可直接创建。
- `bash` 和写入范围未知的扩展/MCP 工具保守锁定 cwd 目录树，同目录/父子目录的写入冲突会被拒绝。扩展覆盖原生工具名时不享有原生工具的细粒度豁免；嵌套 `ctx.executeTool()` 同样经过检查。
- 所有锁仅覆盖该工具执行和结果校验，在 `tool_execution_end` 释放（含失败/取消），不跨越模型思考、网络等待、重试或压缩；回合结束时仍兜底清理。嵌套工具可沿用祖先的保护，但并发兄弟调用仍检查冲突，子调用结束不释放父锁。工具之间靠版本检查防止过期覆盖，不保证整轮修改的事务隔离。冲突工具返回占用者/路径或版本变化原因，Agent 应用 `send_message` 联系同伴或请人协调；不会等待锁、自动抢锁或自动合并。通信和派工工具不占目录写锁。
- 锁范围取 Agent 保存的 `cwd`，不是 prompt 中提到的任务目录；从主目录启动创建的 Agent 可能都保存了 `~`。独立项目应在创建 Agent 时填写各自的实际目录，否则正在执行的 shell/未知工具仍可能短暂阻塞该 cwd 下的其他文件操作。

**`read` 和 `code` 都不是沙箱。** 原生工具和 shell 仍持有当前 OS 用户权限。哈希检查不等于原子文件系统事务，无法阻止检查后的外部进程写入；shell/扩展只有 cwd 协作锁，无法推断目录外、跨符号链接、后台命令以及扩展初始化/命令等非模型工具入口的真实副作用，也没有原生文件工具的版本校验。不要绕过冲突改用 shell 强写或遗留后台写入；频繁冲突或需要并行构建时使用独立 worktree/目录，安全隔离使用受限环境。

仅 code 档位加载已启用的扩展/MCP；创建时通过 Pi 的公开加载器读取该 Agent 工作目录适用的 AGENTS.md 并保存快照；**每次开始任务前重新加载**适用规则到系统提示，包括长期存在的群助手，不需要重建会话。不是每次文件工具调用前自动扫描更深层子目录；进入子目录仍须遵循其适用规则。AGENTS.md 是模型指令，不是 OS 权限边界。

Skills 通过已安装资源发现，可由模型选择读取或由人显式调用；Skills、AGENTS.md 和同伴消息都不能提升工具档位。

同一个 Agent 看过直接输入后，仍可能在后续公开回答中透露这些内容；**不自动广播不等于保密隔离**。通信、文件和凭据的严格隔离需要不同会话与受限运行环境。停止也不能撤销已经发生的外部操作。

## 持久化与恢复

真实数据统一保存在 **`~/.pi-workspaces/`**，首次运行命令自动创建。无论从哪个项目或安装入口启动，同一 OS 用户共用群组、Agent、设置和历史；已有 Agent 保留自己的工作目录，新建 Agent 默认采用启动目录或 `--workspace`。不同 OS 用户仍各自独立。

Demo 数据独立放在 `~/.pi-workspaces/demo/`，但与真实模式共用根目录的独占锁：**同一用户只允许一个 `super-agents` 实例**，不限制其内部 Agent 协作或原生 Pi 会话。`--help`、`--version`、`--models` 和 `--colors` 不占用锁。

旧项目的 `.pi-workspace/`、`.pi-workspace-demo/` 原样保留，**不自动迁移或合并**；新共享工作台不会自动读入旧数据。

```text
~/.pi-workspaces/
  owner.lock                   单进程独占锁
  workspace.sqlite             Agent / 群助手 / 消息 / 投递 / 预算 / 归档 / 派工审批
  sessions/<agent-id>/*.jsonl   Pi 管理的会话上下文
  demo/                        独立演示数据（共用上面的锁）
```

数据目录限制为当前用户访问；内容未加密，可能包含敏感对话。备份时应先退出应用，并保留完整目录。不要手工改写会话或用“最近会话”替换文件映射。

- 正常退出中断活动回合、暂停对应 Agent 并释放锁；待处理消息继续保留。
- 异常退出留下的 `running` 投递在下次启动标记为 `interrupted`，Agent 暂停，**不自动重放**可能有副作用的操作。
- SQLite、Pi JSONL 和外部工具之间没有全局事务。重试前应查看实际文件、工具结果等，不能把“未记为完成”当成“没有执行”。
- 若提示 `Workspace locked`，先根据 `owner.lock` 的 PID 确认旧进程确实停止，再手动移除这个锁文件。不要在进程仍运行时删锁或删数据库。
- 恢复不确定投递使用 `/retry`；只想处理后续消息则 `/resume`。界面在 Agent 页列出投递 ID 和错误。

## 长会话性能

- 折叠工具结果先提取有限行数再排版，避免为了展示 6 行而换行整份文件；运行中保留最新输出，F5 / Ctrl+O 展开仍使用原来的内容上限。
- 历史消息按内容、宽度和展开状态缓存排版，只重绘改变的块；切换视图淘汰旧块，主题/尺寸失效时重新排版。
- 未打开的持久会话只缓存当前一份解析结果，文件路径、大小或修改时间变化后重读；不修改模型上下文或删减 JSONL。
- 未读/完成/排队计数由 SQL 聚合，频道只取可见消息的投递，调度器只取排队项。启动时自动补充索引，不清理历史，也不降低 SQLite 持久化强度。

可重复运行本地合成基准（临时目录、模拟终端，不调用模型、不接触已有工作台）：

```bash
npm run build && node scripts/benchmark-render.mjs
```

基准覆盖 1 / 30 个 32K 字符读取结果、连续流式更新，以及 10,000 条历史投递；输出本机平均耗时，不设硬件相关的测试阈值。它测量本地渲染/查询，不代表模型首 token 延迟；长上下文的服务端推理、网络和自动压缩耗时仍可能增加。
